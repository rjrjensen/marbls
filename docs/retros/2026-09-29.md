## Decisions made

**Tech:**
- Godot 4.7 with statically typed GDScript. C# can't export to the web.
- The Compatibility renderer.
- A 3D board with a tilted camera.

**Architecture:**
- A pure rules core: intents in, events out, a seeded RNG, and JSON save and restore.
- The SignalBus for game-wide events; composition throughout.

**Online stack:**
- A headless Godot server on Fly.io, plus Supabase for accounts and data.

**Web and repo:**
- Cloudflare Pages for the web game. DNS is at Cloudflare; Namecheap is the registrar only.
- The repo is private, and was renamed `marbls`.

**Working agreement:**
- Claude may merge its own PRs when **lint and tests pass**.
- Ideas become GitHub **stories** (issues).
- Rules live in [docs/RULES.md](../RULES.md).

**Rules:** every open question from Kelsey's doc vs. the README is answered; see RULES.md. The notable ones:
- A Jack gets you out of the Bull's Eye.
- The Fast Track must be used on the very next card, and each point of the card is a hop-or-step-off decision.
- Any landing on a corner, even by a swap or a backward Four, counts as being on the Fast Track.
- Starting a marble kills an opponent sitting on your Starting Exit.
- No Bull's Eye entry from your own corner.
- A Joker beats an Ace when cutting.

**Comeback Joker:** per game table for v1. A lifetime version is a story.

## What went well

- **Tests caught real bugs early.** For example, random full games exposed rule interactions, and a save-and-restore test proves games replay exactly. That will matter for online play.
- **Checking in a real browser.** Every UI change was exported and screenshotted in headless Chromium. That caught a washed-out board, a too-small player menu, and an overflowing title bar before anyone saw them.
- **The AI simulation tool paid off immediately.** The first balance run showed the cautious Turtle winning 47% while "evil and smart" Kelsey won 16%. We retuned and added "hunting" so aggressive players chase kills.
- **Small, focused PRs**, merged as soon as they were green, kept marbls.co always playable.

## What was hard, and lessons learned

| Problem | What we learned or did |
| --- | --- |
| github.com downloads are blocked in Claude cloud sessions, even with full network access | Get Godot from the official mirror (`downloads.godotengine.org`); write our own test runner instead of downloading an add-on; pull export templates with HTTP range requests. |
| The environment setup script didn't take effect | A repo-level session-start hook (`.claude/hooks/session-start.sh`) installs Godot and gdlint instead. |
| The Godot 4.7 web engine is 39.5 MB, over Cloudflare Pages' 25 MB file limit | Split the file and join it in the browser. Ryan doesn't like this constraint; options are in [TECH_NOTES.md](../TECH_NOTES.md#ways-to-get-rid-of-the-split). |
| Autoloads (SignalBus) don't exist when Godot runs a bare script | Tests run as a scene (`tests/test_runner.tscn`), started one frame late so they can add nodes. |
| GDScript gotchas | `match` and `pass` are keywords. Don't name functions after built-ins like `wrap`. Every declaration must be typed. |
| The repo was renamed `marbls` | The local git remote still uses the old `Marbles` URL (GitHub redirects). The GitHub tools use `rjrjensen/marbls`. |
| DNS confusion (Namecheap vs Cloudflare) | Once the nameservers point to Cloudflare, *all* DNS records live in Cloudflare. |
| Things we could only partly verify | The win celebration was never seen running in a browser (it needs a full game played to the end). Nothing has been tried on a real phone yet. |
